Abstract. Musculoskeletal simulation tools generally take a muscle, a joint, or a rigid body as their unit of description. Each of those is an open object: it has an input and an output, and closing a loop is something the modeller does afterwards, by wiring. This tool takes the opposite starting point. Its primitive is a circulation — an outbound path and a return path as one indivisible object — because a neuromuscular loop that does not close does not merely perform worse, it fails in a different way.

The consequence is that several properties usually discovered by running a simulation are instead decided from the program text: whether a circuit closes, whether its routes agree with one another, where its identity lies, and whether the anatomy it claims to inhabit can carry it. A lesion that severs a path is a different kind of object from one that attenuates it, and the type system refuses to let a scaling factor imitate a cut at any magnitude.

1. The primitive

A circulation is declared as two phases and the elements that conduct between them. Both phases are mandatory, so an open circuit cannot arise by omission — only through an explicit operator inside an experiment.

circuit postural_loop {
  floor    : derived(resting_cut(spinal_in));

  outbound : cortex -> spinal_in -> alpha_mn -> nmj -> fibre;
  return   : fibre -> spindle -> ia_afferent -> spinal_in -> cortex;

  element descend  conducts cortex      -> spinal_in   delay 12.0 ms;
  element ia_axon  conducts ia_afferent -> spinal_in   delay  8.0 ms gain 1.0;
}

experiment deafferentation {
  intact  : postural_loop;

  lesion attenuated : postural_loop with ia_axon scaling 0.1;
  lesion severed    : postural_loop without element(ia_axon);

  observe : closure_index, divergence_time, band_power(reflex);
}

The two lesions above are not points on one continuum. Attenuation preserves closure at every positive factor; severance opens the circuit outright. This is checked exhaustively over twelve decades rather than sampled, and it is the language's central design commitment.

2. What is decided without running anything

Five analyses run at compile time, on the declaration alone.

Closure and coherence are independent axes, which is not obvious and is worth stating precisely. Over 200 randomly generated circulations, all 200 closed, yet 76 carried a strictly negative coherence margin — disagreements between 4.9 and 29.4 ms, comparable to the loop latencies themselves. Closure asks whether the paths match; coherence asks whether they agree, and the first does not imply the second.

An aperture is a diagnostic, not an error. When a circuit opens, the tool reports where it opened, what circulation lost its return, and what to expect — a failure to resolve rather than degraded precision. Divergence is reported as a time, not raised as an exception, because a backend that threw would be answering a different question than the one asked.

3. Anatomy as a second witness

Everything above reads the program and only the program. That makes the results backend-independent, but it also means the language cannot be wrong about anatomy, because it never mentions any.

A binding attaches compartments to joints of a rig authored by someone who never saw the program, so the joint hierarchy carries an adjacency and a tissue index the source does not — and the two descriptions can disagree.

bind elbow_loop to rig("windows_3d_viewer_flexing_arm") {
  upper_arm   -> "muscle_UpperArm.25_25";
  bicep_belly -> "muscle_Bicep.30_30";
  velocity : 50;
}

The rig used here has 32 joints in three co-registered chains — bone, vein, muscle — with identical topology and rest translations agreeing to 0.0000. That is a compartment index already sitting in the file, and four checks exploit it: adjacency, tissue consistency, reachability, and span.

Two of those fired on circuits written without them in mind. The adjacency check found an element conducting between joints two hops apart, naming the anatomy the program crossed but never mentioned. The span check found that two independent elements both declare delays 5.5× longer than pure conduction over their measured distance predicts — the same ratio for both, which is what one expects when synaptic and excitation–contraction delay dominate and do not scale with axon length.

4. Reading a program out of measurement

The tool also runs backwards. A rig's animation clip is a body-sway record — joint transforms sampled at a fixed rate — so the rambling/trembling decomposition applies to it directly, and the result can be turned back into a circuit whose declared strata reproduce the bands that were measured.

This is where refusal matters more than reporting. A decomposition returns numbers whatever you feed it, so two limits are computed per record and shown before any result:

  • At 30 Hz sampling, Nyquist is 15 Hz. Tremor above that is invisible and would alias into the trembling band.
  • A 1.967 s clip is shorter than one rambling period. Resolving below 0.4 Hz needs 7.5 s.

So on a single pass the panel shows rambling as an em-dash, not a number, and the generated source omits the supraspinal compartment with a comment saying why. Reaching the slow band means looping the clip, and looping injects a peak at 1/clip duration — for this clip 0.508 Hz, inside the trembling band, indistinguishable from a finding. The analysis compares the dominant peak against the known repeat frequency and, when they coincide, writes the refusal into the generated program rather than emitting a number that looks measured.

5. Inverse dynamics from wearable sensors

A shoe pod and a watch are not a force plate: there is no measured ground reaction force, no joint kinematics, no EMG. What there is, per step, is contact time, step frequency, vertical oscillation and speed — and those close the vertical impulse, because over one stride at steady speed the body's vertical momentum returns to where it started.

F_mean = m g / duty          exact, impulse-momentum
F_peak = F_mean × π/2        requires a contact waveform

The first line is a conservation statement, not a fit. The second needs an assumption, and the assumption is named at the point it is used. Results from a 94 s sprint, 42 strides, 4.3–5.6 m/s:

QuantityValueBasis
duty factor0.272measured
contact / flight171 / 149 msmeasured
mean vertical GRF3.68 BWexact
peak vertical GRF5.77 BWhalf-sine assumed
leg stiffness29.2 kN/m+ spring-mass geometry
ankle moment at peak273 N·mquasi-static

Two things the data forced. First, the units were discovered, not assumed: v = length × cadence / k is a redundant identity, and testing it showed the watch and the shoe pod use different conventions (k = 30 and k = 60). Assuming one for both gave 11 BW peak force and 0.43 s flight — impossible, and the signal that something was wrong.

Second, a device's vertical oscillation is the total per-step excursion, while the ballistic rise is the flight arc alone. They differ by the stance dip:

measured 9.9 cm  =  stance dip 7.1 cm  +  flight arc 2.7 cm

The spring-mass model needs the stance dip, and passing the total understated stiffness by a third.

6. Muscle model

A Thelen (2003) Hill-type unit is driven over one stance phase from a prescribed excitation and asked whether it can produce the force inverse dynamics says the tendon carried. It is not fitted to that target: it reaches 9.8 kN against 5.5 kN required. Agreement is a result; a shortfall would also have been one.

Three implementation details worth recording, because each is a place the published equations and the working code differ:

  • The eccentric asymptote cap is in OpenSim but not in Thelen (2003). Without it the force–velocity inverse is singular at the eccentric plateau and the integrator walks into it.
  • The tendon toe/linear constants use the exact expressions, not the paper's rounded ones; a test asserts the slope is continuous at the junction.
  • Thelen's force–velocity expression already contains activation and force–length. Multiplying again — correct for a model whose fv is a pure multiplier — double-counts.

The swing trajectory gives a peak-to-mean speed ratio of exactly 15/8 = 1.875, which is what minimum jerk predicts analytically. Reaching studies report 1.75, so the criterion overshoots by 7.1% — reported rather than smoothed over.

7. Body segment parameters

Segment masses, centres of mass, and inertias come from published anthropometry rather than hard-coded constants, and the two available models are never mixed: de Leva's thigh is 42% heavier than Dempster's because the segments are defined differently. Both close at exactly 100.00% of body mass, which is asserted in tests — a fractional table that does not sum to the whole body is wrong in a way no single row reveals.

Dempster has no female data at all: the sample was eight elderly male cadavers. Asking for it raises an error rather than substituting the male table.

The two implementations agree exactly on every shipped program's arm and closure counts, which is what makes backend-independence a checked property rather than a claim. The IDE compiles on every keystroke, so the static analyses are live before anything is run; execution is a separate act, because that is the architecture the language commits to.

9. Scope

Muscle forces are not identified from wearable data. A joint moment is the net moment, and splitting it between agonist and antagonist is indeterminate without EMG or an optimisation criterion. The muscle model answers "could this muscle do it", not "did it".

Peak forces require a contact waveform the sensors do not record. Joint moments are quasi-static. Moment arms are population values and are the dominant uncertainty in converting a moment into a tendon force. Each of these is a parameter rather than a constant, and each is surfaced in the interface next to the number it conditions.
